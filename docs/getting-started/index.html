    Getting started¶

    Installing¶

    PREFFECT needs Python 3.11 or newer. There is no release on the Python Package Index; it installs from GitHub.

    One command, if you only want to run it¶

    uv tool install git+https://github.com/hallettmiket/preffect

    That builds PREFFECT in an environment of its own and puts a preffect command on your path. There is no copy of the source to keep and nothing to activate. It needs uv.

    The parts used for figures and for grouping samples are optional, because fitting a model does not need a plotting stack. Ask for them by name:

    uv tool install "preffect[viz] @ git+https://github.com/hallettmiket/preffect"

    Later, uv tool upgrade preffect moves you to a newer version and uv tool uninstall preffect removes it.

    On a machine without a GPU¶

    Ask for PyTorch 2.6 from PyTorch's CPU index at the same time:

    uv tool install "preffect @ git+https://github.com/hallettmiket/preffect" \
    --with "torch==2.6.*" --index https://download.pytorch.org/whl/cpu

    Two reasons. The default download of PyTorch carries several gigabytes of GPU libraries a machine without a GPU cannot use; the CPU build is a few hundred megabytes. And from release 2.7 on, PyTorch's CPU kernels are slower, dropout most of all, by about a quarter of a training step on this model; 2.6 is the package's floor, so nothing is lost by staying on it. The measurements are on the speed page. With pip, install torch first and PREFFECT second: pip install "torch==2.6.*" --index-url https://download.pytorch.org/whl/cpu.

    A copy of the source, if you want to change it¶

    git clone https://github.com/hallettmiket/preffect.git
cd preffect
bash scripts/install.sh

    That makes an isolated environment in .venv, installs PREFFECT and everything optional into it, and then checks its own work: that the package imports, that the preffect command runs, and that the fast tests pass. If any of those fail it says so rather than reporting success. Add --minimal for the models, training and inference alone.

    It uses uv when uv is installed, because uv is several times faster, and falls back to the standard library's venv and pip when it is not. It will not download and run an installer from the internet to get uv.

    This route leaves the command at .venv/bin/preffect rather than on your path, which is deliberate: the copy you are editing cannot then be confused with one installed somewhere else.

    Installing it yourself instead¶

    python -m venv .venv
.venv/bin/pip install -e .

    That gives you the models, training and inference. Three extras add the rest:

    .venv/bin/pip install -e '.[graph]'    # the single and full models
.venv/bin/pip install -e '.[cluster]'  # grouping samples, scoring the grouping
.venv/bin/pip install -e '.[viz]'      # the above, plus figures

    Check it worked¶

    preffect --version

    If that prints something unexpected, run it as python -P -m preffect --version. Python puts the current folder at the front of the import path, so a folder named preffect sitting next to where you are standing wins over the one you installed. -P turns that off. This is not hypothetical: it is how the install script's own check first failed.

    The rest of this page writes the command as preffect. If you took a copy of the source instead, write .venv/bin/preffect everywhere it appears.

    What your data has to look like¶

    One folder per split, each containing an .h5ad file, which is the AnnData format:

    my_study/
    train/
        counts.h5ad
    validation/        # optional
        counts.h5ad

    Inside that file:

    • X is the counts: rows are samples, columns are genes. Whole numbers. Not normalised, not log-transformed. PREFFECT models counts, so a log-transformed matrix will not fit and the check below will say so.
    • var_names are the gene names, and they have to be unique. They are the key everything matches on.
    • obs may carry anything you want to use later: a batch, a subtype.
    • obsm['sample_sample_adj'] is the sample-sample network, if you have one. Only the single and full models use it.

    Building that file from the tables you have¶

    Almost nobody's counts arrive in that shape. preffect prepare builds it from the two tables a study does have: the counts, and a row per sample saying what is known about it.

    Say your counts are in counts.csv, one row per sample, with the sample names in the first column and the gene names in the first row:

    ,GENE_0000,GENE_0001,GENE_0002
BX_000,74,66,58
BX_001,90,53,52

    The first cell may be empty, as it is here, or hold a heading of its own.

    and samples.csv has a row per sample, again with the names in the first column:

    sample,subtype,batch,patient
BX_000,basal,A,PT_000
BX_001,basal,B,PT_001

    Then one command writes the file:

    preffect prepare \
    --counts counts.csv \
    --samples samples.csv \
    --out my_study/train \
    --neighbours 10 \
    --label subtype

    tissue 1: 60 samples and 400 genes from counts.csv, read as samples-by-genes
  3 annotation(s) per sample from samples.csv
  tissue 1: 60 samples, 371 edge(s), 12.4 per sample (fewest 10, middle 11, most 19); no isolated samples
  tissue 1: 100.0% of edges join two samples with the same subtype, against 32.2% if the edges ignored it
wrote my_study/train/counts.tau_1.h5ad
check it with: preffect check --train my_study/train

    Four things in that command are worth knowing about.

    --counts-are genes-by-samples reads a counts table written the other way round, one row per gene, which is how many pipelines write one. Without it the table is read as one row per sample, and a table the wrong way round is refused rather than transposed on a guess.

    --neighbours 10 builds the sample-sample network the single and full models need, by linking each sample to the ten others whose counts look most like its own. Leave it out and no network is written, which is right for the simple model. Ten is the number this project measured; the command line page says where it comes from. If your files already exist and only the network is missing, preffect network adds one to them without this command.

    --label subtype says whether the network found anything. It compares the share of links joining two samples with the same subtype against the share that would do so if the links ignored subtype entirely. The second line above is a network that found real structure. Two numbers close together mean it found none, and a graph model over that network will cost ten times the parameters of the simple model for nothing.

    It refuses rather than repairs. Counts that are not whole numbers, a negative count, a repeated gene name, a sample table describing different samples from the counts: each stops the command with a sentence naming the entries at fault.

    For the full model, give --counts and --samples once per tissue and name the column that says which patient each sample came from. That builds the correspondence table the full model needs, and a patient with no sample in some tissue is kept with a gap recorded rather than dropped.

    Always run the check first¶

    preffect check --train my_study/train --validation my_study/validation

    This reads the data, reports what it found, and refuses if something would stop a run. It takes seconds and it is the single most useful command here, because the problems it finds are ones that otherwise show up as a confusing result rather than as an error.

    On real data it has caught, among other things, twenty-one genes all sharing one name, a validation set that was a byte-for-byte copy of the training set, and a sample-sample network with no edges in it.

    Output on a healthy dataset:

    training: 1 tissue(s) from my_study/train
  tissue 1: 528 samples, 18790 genes, a network with 105 edge(s), 1.0 per sample
  the counts look usable
validation: 61 samples from my_study/validation
  tissue 1: 0 of 528 training samples reappear in validation

    Fitting a model¶

    preffect train \
    --train my_study/train \
    --validation my_study/validation \
    --out model.pt \
    --epochs 100 \
    --seed 0 \
    --threads 16

    Two of those are worth knowing about.

    --seed makes the run repeatable. Without it the same command gives a different model each time.

    --threads matters more than you would expect. PyTorch otherwise starts one compute thread per core, which on a large shared machine can be over a hundred, and coordinating them costs more than the arithmetic. The right number depends on the size of the data. Measured on 528 samples by 18,790 genes, seconds per epoch:

    threads 1 4 8 16 32
    seconds per epoch 3.9 2.1 1.3 1.2 1.6

    On small data the ordering reverses and one thread wins. The default of 4 suits a small test rather than a real cohort.

    Applying it¶

    preffect apply \
    --model model.pt \
    --data my_study/train \
    --out cleaned.h5ad

    The result carries the cleaned counts in X, the predicted proportions in layers['composition'], and the latent summary in obsm['latent'].

    Genes are matched to the ones the model was fitted on by name, so the column order of the file you apply to does not have to match the one you trained on. If a gene is missing, it says so rather than quietly shifting everything along by one.
